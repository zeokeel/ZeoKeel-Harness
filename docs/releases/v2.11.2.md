## 一、本版修复：历史企微会话的自动授权真正生效

### 1. 问题

v2.11.1 的断言端点只接受 `identity.external` 登录后形成的 RBAC 身份（`external_source=rbac`）。但存量企业微信登录用户的 `external_source` 仍是 `wecom`，因此：

- 已经绑定了 RBAC 权限的员工，登录后仍拿不到断言，自动授权静默回退扫码；
- 若直接打开全局 `identity.external`，未在 RBAC 绑定的员工会被登录链路拒绝，风险不可接受。

### 2. 修复

断言端点在“当前会话不是 `rbac` 外部身份”时，按需调用已配置的 RBAC 只读解析接口，把企微登录身份映射到 RBAC uid：

- 解析成功且状态正常 ⇒ 用该 uid 签发短时断言，后续 token exchange 不变；
- 解析不到 / 已停用 / 非企微 / 超时 / 服务不可用 ⇒ 409，客户端静默回退交互式授权；
- **登录链路完全不变**：`identity.external.enabled` 仍可保持 `false`，未绑定员工正常扫码登录；
- 解析接口与令牌复用现有 `identity.external.endpoint/token` 配置（令牌只加密存储、只走 Header、不落日志）；
- 只在 `connector.auto_auth.enabled=true` 且连接器在白名单内、已认证请求上触发；
- 原有 `external_source=rbac` 用户路径零改动。

### 3. 验证口径

- 已绑定企微会话：断言端点返回 200，RBAC token exchange 返回 200，令牌主体与绑定 uid 一致；
- 未绑定企微会话：断言端点返回 409，扫码登录不受影响；
- bootstrap 下发 `auto_auth="rbac-assertion"`、`auto_connect=true`，与客户端 2.11.1+ 的自动连接链路一致；
- 本版无数据库迁移，回滚只需换回镜像并关闭自动授权开关。

## 二、升级与配置

1. 服务端升级本版镜像；
2. 在管理后台「认证配置 → 外部权限源」保存 `endpoint` 与 `token`（可保持 `enabled=false`；断言端点按需读取该配置），`methods` 至少包含 `wecom`；
3. 保持或打开 `connector.auto_auth.enabled`，并把需要自动授权的连接器加入白名单、设置 `auto_connect=true`；
4. 已绑定 RBAC 的员工重新登录即可自动连接；未绑定员工继续走原扫码流程；
5. RBAC 侧需保持 token exchange 与只读身份解析接口可用（与 v2.11.1 相同）。

## 四、边界与回滚

- 自动授权只对**已在 RBAC 绑定**的员工生效；未绑定员工保持扫码回退；
- 当前身份解析仅覆盖企业微信 `wecom` 登录；其它 IdP 仍按原行为回退；
- 需 RBAC 侧 token exchange 与身份解析接口可用，否则仅自动授权失败，不影响登录；
- **回滚**：关闭 `connector.auto_auth.enabled` 即恢复原扫码流程；服务端可回退上一版镜像；无数据库迁移。
