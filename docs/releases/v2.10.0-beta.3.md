> 一句话：修复"服务端门户页 / 管理后台 / 内置演示应用显示上一个项目 logo"的三条品牌漂移来源，并把"渠道包里的品牌素材必须等于公开仓品牌真源"变成构建期判据；产品功能与 `v2.10.0-beta.2` 相同。

## 一、为什么会有 v2.10.0-beta.3

- **现象**：服务端门户页与 `/admin/` 管理后台的品牌标识是**上一个项目的几何**；应用平台内置演示应用 **showcase**（能力全集）的顶栏与 403 页同样是旧 mark。
- **根因（渠道侧）**：门户页与管理后台都渲染 `GET /api/client/v2/channel/logo`，字节来自镜像内 `/opt/zeokeel/channel/`（构建期从私有渠道仓复制）。公开仓 2026-10-21 更换品牌几何后，渠道仓里公共渠道（`official` / `beta`）的素材仍是旧字节，而既有渠道包判据只看字段与形状、**没有一条看字节** ⇒ 流水线全绿、旧 mark 上线。
- **根因（演示应用侧）**：showcase 的品牌标识是**手抄**在 `web/index.html` 与 `main.go` 里的旧几何（"括号 + 连接线 + 节点圆"），换品牌后无人再动它；既有判据只看得到"页面上有 SVG"。
- **修法**：
  1. 私有渠道仓的 `official` / `beta` 素材按公开仓 `brands/official/{logo.svg,logo-dark.svg}` 逐字节重同步；并加 `.gitattributes`（`* -text`）关闭 git 换行转换 —— 否则 Windows 检出会把 LF 变 CRLF，让"逐字节相同"的判据在 Windows 打包 job 上假红。
  2. 公开仓新增**构建期字节判据**：公共渠道目录里出现的品牌素材必须与 `brands/official/*` 逐字节相同（公告渠道缺素材仍合法、品牌渠道不受约束），配旧字节必红的回归用例。
  3. 演示应用改为引用应用资源里的**品牌真源逐字节副本**（白天/夜间两版，按 `prefers-color-scheme` 选边），并加回归判据：字节对拍、打包接线、403 页同源、全树禁止手绘几何特征串。

## 二、品牌几何的渠道侧与演示应用修复

- 渠道侧（影响门户页、管理后台、客户端随包素材）：公共渠道的品牌素材与公开仓真源逐字节一致；构建期一旦漂移即 fail-loud（错误只点名字段与真源路径，不回显渠道侧取值）。
- 演示应用侧（影响应用平台内置 `demo-showcase`）：顶栏与 403 页改用 `/static/brand-day.svg` / `brand-night.svg`（= `brands/official/logo.svg` / `logo-dark.svg` 的逐字节副本），本地构建入口与镜像 Dockerfile 的打包清单同步登记这两份资源。
- 回归面：`server/demoapps/showcase/brand_test.go`（逐字节 / 接线 / 403 页同源 / 全树禁止旧几何）与 `scripts/lib/check-channel-json.test.mjs`（旧字节必红 / 真源副本放行 / 品牌渠道不误伤）。

## 三、验收与上线自检

本版在构建期新增的判据之外，上线后按下面几条核对（服务端地址替换成自己的）：

```bash
# 门户/后台的品牌标识字节必须等于公开仓真源（sha256 见 brands/official/）
curl -s https://<server>/api/client/v2/channel/logo      | sha256sum   # = brands/official/logo.svg
curl -s https://<server>/api/client/v2/channel/logo-dark | sha256sum   # = brands/official/logo-dark.svg
curl -s https://<server>/api/client/v2/channel/favicon   | sha256sum   # = brands/official/logo.svg
curl -s -o /dev/null -w '%{http_code}\n' https://<server>/          # 门户页 200
curl -s -o /dev/null -w '%{http_code}\n' https://<server>/admin/    # 管理后台 200
```

演示应用是**播种**出来的（只落库、不随镜像热更新）：已有部署升级到本版后，需要把旧的 `demo-*` 应用删掉再重启服务端，让它按新版 `demos.json` 重新播种，才能看到新的品牌标识。演示应用的数据是演示数据，删除不影响业务数据。

## 已知限制

- 本版是**预发布**：只走 beta 渠道，不进入正式更新通道，正式客户端不会自动收到。
- 市场「按版本下载/版本历史」「市场审批历史面」「市场精选」「审批队列分页/批量」仍为产品待定项（同 `v2.10.0-beta.2`），现有 UI 不渲染假入口。
- 既有已发布 tag 的镜像与客户端安装包携带的是构建期固化的旧品牌素材；本版是第一个把渠道侧与演示应用侧都修好的预发布版本。
- 1 vCPU / 2 GiB 的演示机仍受 WASM `small` 档限制（1 并发），多人同时演示会排队。

## 升级与回滚

- 服务端：取本版镜像附件（`zeokeel-server-2.10.0-beta.3-amd64.zip`）→ `docker load` → 改部署的 `SERVER_IMAGE` → `docker compose up -d`；升级前备份数据库与数据卷。
- 客户端：随服务端镜像分发，员工从自己登录的服务器取包。
- 回滚：切回上一版镜像即可（本版无迁移、无数据格式变化）；演示应用若要回到旧标识，同样需要删掉 `demo-*` 后按旧镜像重新播种。

- **迁移清单（机器可读锚点，供 `scripts/check-release-notes-migrations.mjs` 与 `git diff` 对拍）**：无

## 附件与校验

- `zeokeel-server-2.10.0-beta.3-amd64.zip`：服务端镜像压缩包（`docker load` 后使用）；
- `SHA256SUMS`：`sha256sum -c SHA256SUMS` 校验后再解压；
- 桌面客户端安装包：Linux / Windows / macOS 三个平台随 Release 附件发布。
