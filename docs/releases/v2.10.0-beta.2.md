# v2.10.0-beta.2（2026-10-26）

> 一句话：修复预发布 tag 的 Windows 安装器验收路径，使 beta 发布链能真正产出并发布安装包；产品功能与 `v2.10.0-beta.1` 相同。

| 项目 | 说明 |

| 版本类型 | **预发布（beta）** |
| 升级建议 | 建议测试升级；测试环境请先备份数据库 |
| 影响面 | 桌面客户端（Linux / Windows / macOS）/ 服务端镜像 / 管理后台 |

## 一、为什么会有 beta.2

- **现象**：`v2.10.0-beta.1` 的 tag 发布在 Windows 安装器验收步骤失败，`release` job 被跳过。
- **根因**：预发布 tag 只构建 beta 渠道，`client-assets/` 下只有 `<beta>/`；验收脚本硬编码扫描 `client-assets/official/`，于是 `ENOENT`。
- **修法**：验收入口改为 stable 优先 `official/`、预发布使用唯一渠道目录；多目录且无 official 时明确失败，不猜目录。组件测试覆盖两种形态。
- **不会影响客户**：beta.1 未产出可下载产物；本版功能与 beta.1 相同。

## 二、包含的能力中心变更（与 beta.1 相同）

- 能力中心客户端现代化重构：`全部 / 已安装 / 我上传 / 市场` 四分段、搜索/排序/网格列表、整页详情、骨架与空态；`source=own` 提交面、卸载刷新、官方更新、409 分档、上传版本预检。
- 发布/删除/审核安全：已通过版本删除 409、空壳释放、normalize 走统一发布内核、semver 投影、直发/审批同权、原子下架冻结、审核三面收敛、归属转移与发布串行。
- 管理端：中文展示名、权限门、术语与官方标记；迁移 0090（授权索引 + quality CHECK）。

## 三、迁移状态（继承 beta.1）

本版未新增迁移；`v2.10.0-beta.1` 已包含 0086–0090（WASM 部署历史/限流/真删两阶段/诊断版本、能力中心授权索引与 quality CHECK）。

- **部署注意**：0090 的索引创建不是 `CONCURRENTLY`，大表请在低峰窗口升级；旧版二进制与该组加法迁移兼容。

## 四、beta.2 限制

- 市场「按版本下载/版本历史」「市场审批历史面」「市场精选」「审批队列分页/批量」为产品待定项，本版未实现；现有 UI 不渲染假入口。
- `author` 在组织/市场渠道仍分别表示上传者/负责人（管理端已用「作者（上传者）/归属（负责人）」两列区分）。
- 预发布版不进入正式更新通道，正式客户端不会自动收到本版。

## 五、升级与回滚

- 服务端：取本版镜像附件，按 `docs/deploy/AI-DEPLOY.md` 升级；升级前必须备份数据库。
- 客户端：随服务端镜像分发，员工从自己登录的服务器取包。
- 回滚：0086–0090 均为加法迁移，旧版二进制可继续运行；切回旧镜像前请确认数据库已备份，确需删除约束/索引时按对应迁移文件注释手工处理。

- **迁移清单（机器可读锚点，供 `scripts/check-release-notes-migrations.mjs` 与 `git diff` 对拍）**：无

## 附件与校验

- `zeokeel-server-2.10.0-beta.2-amd64.zip`：服务端镜像压缩包（`docker load` 后使用）；
- `SHA256SUMS`：`sha256sum -c SHA256SUMS` 校验后再解压；
- 桌面客户端安装包：Linux / Windows / macOS 三个平台随 Release 附件发布。
