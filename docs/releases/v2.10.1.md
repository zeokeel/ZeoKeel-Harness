# v2.10.1（2026-11-03）

> 一句话：把 OEM 渠道集恢复为**全部渠道**并随本版一起构建；产品代码与 `v2.10.0` 完全相同，取新镜像即可获得完整的渠道产物。

## 一、为什么会有 v2.10.1

- **现象**：`v2.10.0` 的发布链按私有渠道仓里当时的渠道集构建，只覆盖了新仓已有的渠道；历史线上的一个品牌渠道在新仓里没有对应渠道包 ⇒ 该渠道的客户在 2.10.x 上拿不到产物。
- **修复**：把缺的品牌渠道包恢复进私有渠道仓（素材取自历史线上镜像的渠道目录，未重画），渠道仓期望集合与公开仓的渠道目录数下限同步为 4；本版正式 tag 按**全部 4 个渠道**构建并发布。
- **产品代码与 `v2.10.0` 相同**：本版不包含功能修复，仅为渠道构建与发布面补全。

## 二、渠道产物与交付

- 正式 tag 构建全部渠道：公开渠道（official / beta）照旧进入 GitHub Release 与更新服务器；品牌渠道只发布到更新服务器各自目录，不进入公开 Release（既有定策不变）。
- 本版 OEM 渠道集恢复为全部渠道（4 个），此前缺失的那个品牌渠道从本版起重新获得升级线。

## 已知限制（本版认账，未修）

- 与 `v2.10.0` 相同：市场「按版本下载/版本历史」「市场审批历史面」「市场精选」「审批队列分页/批量」仍为产品待定项；`author` 在组织/市场渠道的语义差异由管理端两列区分。
- 本版只变更渠道内容与发布链判据，客户端与服务端行为与 `v2.10.0` 一致。

## 升级与回滚

- **服务端**：取本版镜像压缩包 → `docker load` → 修改部署的 `SERVER_IMAGE` → `docker compose up -d`；按 `docs/deploy/AI-DEPLOY.md` 执行，升级前建议备份。
- **客户端**：随服务端镜像分发，服务端升级后员工从自己登录的服务器取包。
- **迁移**：本版无新增迁移（与 `v2.10.0` 相同的库结构）。
- **回滚**：切回上一版镜像即可（无迁移、无数据形状变化）。

- **迁移清单（机器可读锚点，供 `scripts/check-release-notes-migrations.mjs` 与 `git diff` 对拍）**：无

## 附件与校验

- `zeokeel-server-2.10.1-amd64.zip`：服务端镜像压缩包（`docker load` 后使用）；
- `SHA256SUMS`：`sha256sum -c SHA256SUMS` 校验后再解压；
- 桌面客户端安装包：随服务端镜像分发，员工从自己登录的服务器取包（不单独挂在 Release 上）。
