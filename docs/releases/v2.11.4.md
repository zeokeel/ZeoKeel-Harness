## 一、管理后台统一分发客户端插件

- **现象**：企业内所有员工都需要同一个桌面插件时，过去只能逐台手动安装或随客户端预置，管理后台无法统一发放。
- **影响**：本版 webadmin 新增「插件」页。管理员上传 DSH bundle 的 `.tgz`（`npm pack` 产物）并启用后，所有登录员工通过已认证的 bootstrap 拿到同一份清单。
- **行为**：客户端下载后校验 sha256/大小/包名/版本，用 profile 插件管理器安装；首次安装需要重启客户端生效。之后每次登录补装缺失或版本不符的包。停用/删除只停止下发，不自动卸载已安装插件。
- **边界**：本版没有按人/部门分配、状态合规、强制禁用、版本历史或签名；信任边界是 TLS + 管理员 RBAC + sha256。插件与宿主同进程、没有插件沙箱，只允许可信管理员上传。

## 二、升级注意

- 服务端与桌面客户端需要一起升级才能使用自动分发；只升级服务端时旧客户端忽略新字段，行为不变。
- 新增迁移 0091；升级前请备份数据库，按 `docs/deploy/AI-DEPLOY.md` 执行。
- 管理端插件页使用独立权限 `plugin:read` / `plugin:write`；没有权限的账号看不到写入口。

## 已知限制（本版认账，未修）

- **首次安装需重启**：插件在客户端 profile 组合完成后才能加载；下载安装成功后会提示重启，不会静默重启。
- **无按人/部门分配**：本版是全员同一份清单；需要按部门/个人分发请等待后续版本。
- **无签名/状态合规**：当前只靠 TLS + 管理员 RBAC + sha256；没有客户端安装状态上报、强制禁用或版本回滚 UI（回滚 = 重新上传旧版本）。
- **旧客户端不自动获取**：旧版本客户端忽略 bootstrap `plugins` 字段，继续手动安装/MDM。

## 升级与回滚

1. 升级服务端镜像（启动时自动执行 0091 迁移）；
2. 升级桌面客户端到本版（自动分发需要新版客户端）；
3. 在 webadmin「插件」上传 `.tgz` 并启用；
4. 员工登录客户端后按提示重启。

升级前必须备份；不要使用 `latest`，不要 `down -v`。

**回滚**：webadmin 停用/删除插件即停止下发；回退服务端镜像不会自动删除 `client_plugins` 表（旧二进制忽略它）；已安装插件保留在客户端 profile，可手动移除。

## 附件与校验
