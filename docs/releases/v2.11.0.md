# v2.11.0（2026-11-09）

> 一句话：这一版把企业微信 / 钉钉扫码登录做成完整的客户端登录方式，并接入 RBAC 外部身份源；登录页改为「点登录 → 浏览器扫码 → 客户端自动进入」，账号区显示员工真实姓名和登录来源。RBAC 解析默认关闭，不配置时不影响现有部署。

| 升级建议 | 建议升级（服务端取新镜像；客户端随镜像分发） |

| 产品代码变化 | **有**（相对 `v2.10.1`：新增扫码登录与 RBAC 外部身份源；相对 `v2.11.0-beta.2` 无代码变化） |

## 访问模型变更（升级必读）

- **变化**：登录页改为「品牌主视觉 + 一个主登录按钮」：点击后打开系统浏览器展示企业微信 / 钉钉官方扫码页，扫码确认后客户端自动进入主界面；账号区显示员工真实姓名与登录来源。
- **必须同版本升级**：服务端与客户端**建议同版本**——浏览器扫码自动进入依赖服务端新增的扫码会话 / 回调 / 轮询接口。旧版客户端升级后重新登录一次即可带出姓名与来源。
- **保留的入口**：本地账号登录保留为二级入口；客户端内扫码保留为兜底；浏览器未自动打开时可复制登录链接或重新发起登录。
- **运维要做什么**：扫码登录是**可选配置**——在企业微信 / 钉钉开放平台配置回调地址，并在管理后台「认证配置」填写应用凭据；RBAC 外部身份源**默认关闭**，不配置时行为与 `v2.10.1` 一致。

## 一、这一版带来的能力

### 1. 企业微信 / 钉钉扫码登录

- 服务端新增企业微信、钉钉扫码登录流程（二维码启动、回调、轮询、用户建档）；
- 管理后台「认证配置」新增企业微信 / 钉钉扫码登录配置：AppKey、AppSecret、回调地址等；
- 客户端登录页支持企业微信 / 钉钉两种扫码方式；
- 登录页改为「点登录 → 系统浏览器扫码 → 客户端自动进入」：
  - 品牌主视觉 + 主登录按钮；
  - 企业微信 / 钉钉图标切换，默认企业微信；
  - 点击登录后打开系统浏览器展示官方扫码页；
  - 客户端保持「登录中…」，扫码确认后自动进入主界面；
  - 浏览器没有自动打开时，可复制登录链接或重新发起登录；
  - 保留本地账号登录为二级入口，以及客户端内扫码兜底。

### 2. 账号卡显示真实姓名与来源

- 登录会话携带服务端下发的 `display_name` 和登录来源（`local` / `wecom` / `dingtalk`）；
- 左下角账号区显示员工真实姓名，不再显示 RBAC uid；姓名前显示企业微信 / 钉钉品牌图标；
- 旧会话需要重新登录一次才会带出姓名和来源。

### 3. RBAC 外部身份源（默认关闭）

- 服务端支持在扫码回调后调用 RBAC 的 `/internal/v1/identity/resolve` 解析员工身份；
- 解析成功后以 RBAC uid 建档，支持同步部门到本地组；
- 404 / 409 / 停用 / 服务不可用等情况 fail-closed，并映射为可本地化的登录失败文案；
- 管理后台新增外部身份源配置：服务地址、访问令牌、适用的扫码方式、超时、部门同步开关；
- **默认关闭**，未配置 `identity.external` 的部署保持原有行为。

## 二、与 v2.10.1 的关系

- 本版在 `v2.10.1` 基础上新增上述扫码登录与外部身份源能力；相对 `v2.11.0-beta.2` 产品代码相同（beta 线已验证的功能转正）。
- 本版**没有新增数据库迁移**，库结构与 `v2.10.1` 一致；升级只需替换服务端镜像，客户端随镜像分发。
- 渠道内容与客户端安装包由发布链按渠道仓构建，本文件只描述产品行为。

## 已知限制（本版认账，未修）

- 浏览器是否自动打开取决于操作系统与默认浏览器；打不开时使用「复制登录链接」。
- 钉钉官方扫码页在已登录钉钉的浏览器中可能显示「立即登录」而不是二维码；两种方式都会完成授权。
- 企业微信 / 钉钉回调地址必须与开放平台登记一致，否则扫码后无法完成登录。
- RBAC 身份解析失败时登录会拒绝，不会回退成本地账号。

## 升级与回滚

- **服务端**：取本版镜像压缩包 → `docker load` → 修改部署的 `SERVER_IMAGE` → `docker compose up -d`；按 `docs/deploy/AI-DEPLOY.md` 执行，升级前建议备份。
- **客户端**：随服务端镜像分发，服务端升级后员工从自己登录的服务器取包；旧版客户端升级后重新登录一次。
- **迁移**：本版无新增迁移（与 `v2.10.1` 的库结构一致）。
- **回滚**：切回上一版镜像即可（无迁移、无数据形状变化）。

- **迁移清单（机器可读锚点，供 `scripts/check-release-notes-migrations.mjs` 与 `git diff` 对拍）**：无

## 附件与校验

- `zeokeel-server-2.11.0-amd64.zip`：服务端镜像压缩包（`docker load` 后使用）；
- `SHA256SUMS`：`sha256sum -c SHA256SUMS` 校验后再解压；
- 桌面客户端安装包（macOS / Windows / Linux）：随服务端镜像分发，员工从自己登录的服务器取包（不单独挂在 Release 上）。
