> 一句话：修正 `v2.11.0-beta.1` 的发布链登记与发布说明迁移锚点，产品代码与 beta.1 相同；本版继续提供企业微信 / 钉钉扫码登录、浏览器扫码自动进入和 RBAC 外部身份源。

| 项目 | 说明 |
| --- | --- |

## 一、为什么会有 v2.11.0-beta.2

- `v2.11.0-beta.1` 在发布流水线的「发布说明迁移清单」判据处失败：新 tag 没有登记进 `RELEASE_CHAIN`，发布说明也缺少机器可读的迁移锚点；因此没有产出任何发布产物。
- 本版把 `v2.11.0-beta.2` 追加到发布链，并补齐发布说明的机器锚点；产品代码与 beta.1 相同。
- 由于 beta.1 的 tag 受发布 tag 保护规则约束、不可移动，本版按仓库惯例作为它的替代发布。

## 二、这一版包含的功能

- 企业微信 / 钉钉扫码登录：服务端二维码启动、回调、轮询与用户建档；
- 管理后台认证配置：企业微信 / 钉钉应用凭据、回调参数与 RBAC 外部身份源；
- 登录页改为「点登录 → 系统浏览器扫码 → 客户端自动进入」：
  - 品牌主视觉 + 主登录按钮；
  - 企业微信 / 钉钉图标切换，默认企业微信；
  - 登录中状态、复制链接与重新发起登录兜底；
  - 保留本地账号登录与客户端内扫码兜底。
- 账号区显示员工真实姓名与登录来源图标；旧会话需重新登录一次。
- RBAC 外部身份解析默认关闭；启用后按 RBAC uid 建档，失败 fail-closed，并支持同步部门。

## 三、升级注意事项

1. **先升级服务端，再升级客户端**：扫码登录依赖服务端新的二维码/回调接口。
2. 在对应开放平台配置回调地址，并在管理后台填写企业微信 / 钉钉应用凭据。
3. RBAC 外部身份源是可选配置；启用前确认服务地址、令牌与返回契约，先在测试环境验证。
4. 旧客户端会话升级后重新扫码登录一次，即可显示真实姓名与登录来源。
5. beta 包用于验证，不建议直接替换生产正式渠道。

## 四、beta.2 的已知限制

- 浏览器是否自动打开取决于操作系统与默认浏览器；打不开时使用「复制登录链接」。
- 钉钉官方扫码页在已登录钉钉的浏览器中可能显示「立即登录」而不是二维码；两种方式都会完成授权。
- 企业微信 / 钉钉回调地址必须与开放平台登记一致，否则扫码后无法完成登录。
- RBAC 身份解析失败时登录会拒绝，不会回退成本地账号。

## 五、验证与回滚

- 已通过客户端登录页、扫码会话映射、RBAC 身份解析、WebAdmin 认证配置及全量门禁用例。
- 已用真实企业微信 / 钉钉账号完成浏览器扫码 → 客户端自动进入的端到端验证。
- 回滚：回退本版本部署即可；RBAC 外部身份源默认关闭，回滚不影响未启用的部署。
- **迁移清单（机器可读锚点，供 `scripts/check-release-notes-migrations.mjs` 与 `git diff` 对拍）**：无
