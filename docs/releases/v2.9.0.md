# v2.9.0（2026-10-22）

> 一句话：`v2.8.3-beta.5` 转正 —— Windows 客户端改为**一键安装、仅当前用户、静默升级**，
> 新增**启动失败安全模式**，并把安装器与更新链从"只能人工验"变成 CI 里的行为级门禁。
> 如果你是 Windows 用户且装过改名前发布的 2.8.x（尤其是全局安装），**升级前先看第一节**：
> 本版不会静默覆盖旧安装，需要先卸载旧版本。

| 项目 | 说明 |
| --- | --- |
| 版本类型 | **正式版（Latest）** |
| 升级建议 | **必须升级**（Windows 安装方式换代 + 旧版迁移检查 + 启动恢复） |
| 影响面 | 桌面客户端（Linux / Windows / macOS）+ 服务端镜像 |
| 产品代码变化 | 有（相对 `v2.8.2`；相对 `v2.8.3-beta.5` 只有桌面运行时的安装器、启动恢复与门禁） |
| 数据库迁移 | 无 |

## 一、Windows 客户端：一键安装、静默升级（升级必读）

- **变化**：Windows 安装器从"向导式（选目录/许可页）"改为**一键**：双击即装，不需要管理员权限，
  不出现任何向导页面，装完自动启动；只安装到当前用户。
  安装目录是 `%LOCALAPPDATA%\Programs\dsh-plugin-desktop`（目录名由打包器的包名派生），
  品牌名出现在开始菜单、窗口标题与可执行文件上。
- **升级不再弹向导**：应用内的"重启并安装"现在用 `/S --updated --force-run` 静默原地升级，
  装完自动重新打开应用。没有界面，也不会因为界面弹框把更新卡住。
- **旧版迁移（重要）**：改名前发布的 2.8.x 安装器与本版使用不同的安装标识，
  **本版不会静默覆盖它们**。检测到旧安装时：
  - 交互安装会直接提示"请先卸载旧版本"，并写一份诊断到 `%TEMP%\zeokeel-harness-legacy-install.txt`；
  - 静默更新会以退出码 2 结束（不装第二份、也不挂起），应用内的更新入口会先弹原生提示并保留已下载的安装包；
  - 旧版若安装在"所有用户"（Program Files）下，必须先在「设置 → 应用」里手动卸载 ——
    按用户安装的安装器无法在不提权的情况下删除它。
- **数据根变化**：改名前使用的数据根与当前产品不同名，旧会话与设置**不会**自动迁移。
  需要保留历史数据时，先备份旧数据根，再按需迁移到新数据根（`~/.zeokeel-harness` 或你的渠道数据根）。
- **验证**：CI 在 Windows 打包后会对官方产物真实执行 静默安装 → 重装（仍是单份）→ 静默卸载，
  并先种入旧版安装标识验证"必须停下且不落盘"。

## 二、启动失败不再只能删目录：安全模式与补丁备份

- **现象**：以前第三方插件或手改过的配置补丁把启动弄坏时，用户只能去删数据目录（顺带丢会话）。
- **修复**：致命启动错误面新增两个出口：
  - **安全模式（跳过第三方插件）**：下次启动不加载第三方插件 bundle；**不改动你的补丁**；
    启动成功后自动退出安全模式（一次性，不会永久禁用）。若一个第三方插件都没有，则改为备份补丁。
  - **备份补丁并重启**：把用户级补丁（profile 与数据根补丁）改名为带时间戳的 `.bak`，从空补丁启动。
- **不会死循环**：重复点安全模式且上一次仍失败时，会**自动升级**为"同时备份补丁"；
  连补丁都没有时明确报错并保持非零退出，而不是假装成功。
- **坏状态自愈**：插件管理状态损坏、或里面残留"禁用安装自带组件"的无效条目时，
  现在会被忽略并清理（写日志），不再导致客户端永久起不来。

## 三、更新与交付链的加固

- **许可证随包**：一键安装器不再显示许可页，因此 `LICENSE` 与第三方声明
  `THIRD_PARTY_NOTICES.md` 改为随安装包落到 `resources/`，并纳入产物断言。
- **更新链行为门禁（CI）**：对官方 Windows 产物做两件事 ——
  ① 解包断言安装器载荷里确实有许可证声明与应用主程序；
  ② 在没有残留的机器上真实执行"静默安装/重装/静默卸载"，并带旧版负例。
  每一步都有硬超时：静默挂起会让 CI 直接红，而不是卡住发布。
- **保留原有口径**：服务端与客户端同版本升级；客户端安装包随镜像与更新入口分发。

## 四、自上一个正式版 `v2.8.2` 以来的其他变化（预发线已发布）

- **品牌与命名**：整仓切换到新品牌标识（三平台图标、官网、管理后台、登录页），
  历史迁移与守卫记录保持原字节。
- **上游与运行时**：上游固定点升级到 `dsh-v0.2.1-rc.2`；自动化任务改用官方 Schedule，退役自研 cron。
- **客户端修复**：升级后不再每次启动被登出（会话恢复与竞态）；侧栏菜单改为实底背板；
  技能管理白屏与设置入口偶发无响应修复；macOS 支持原地替换应用包完成自更新。
- **渠道与交付**：渠道可声明功能模块与交付平台，构建期按渠道裁剪；三平台打包与更新链修复。

## 已知限制

- **Windows 安装器仍未代码签名**：首次双击可能出现"未知发布者"/SmartScreen 提示；
  静默升级因为没有界面，被拦截时的表现是"更新看起来没发生"，请重新检查更新或手动安装。
  签名到位后会单独发版说明。
- **旧版（改名前）安装的数据根不迁移**：旧全局安装必须先手动卸载；旧会话/设置需要自行备份迁移。
- **Windows 每次更新下载完整安装包**（无差分更新）；**Linux 仍为 AppImage**，新版本需要手动替换。
- 同一台机器的不同渠道共用同一个 Windows 安装目录名，渠道数据靠各自的数据根分离。

## 升级与回滚

- **服务端**：取 `zeokeel-server-2.9.0-amd64.zip` → `docker load` → 按 `docs/deploy/AI-DEPLOY.md`
  升级（**升级前必须备份**整个数据根，不要使用 `latest`，不要 `down -v`）。
- **客户端**：随服务端镜像/更新入口分发；服务端与客户端保持同版本。
- **迁移清单（机器可读锚点，供 `scripts/check-release-notes-migrations.mjs` 与 `git diff` 对拍）**：无
- **回滚**：口径唯一真源是 `docs/deploy/AI-DEPLOY.md` §7。本版相对 `v2.8.3-beta.5` **没有数据库迁移**，
  回滚只需换回上一版镜像与上一版客户端包。Windows 若要从本版退到向导式安装器的旧版本，
  建议先卸载本版再安装旧版包（两代安装器不共享升级路径）。

## 附件与校验

- `zeokeel-server-2.9.0-amd64.zip`：服务端镜像压缩包（`docker load` 后使用），内含该渠道的三平台客户端安装包；
- `SHA256SUMS`：先 `sha256sum -c SHA256SUMS` 校验，再解压。
- 客户端安装包在镜像内（`/opt/zeokeel/client/`），员工也可从自己服务器的更新页面下载。
  品牌渠道的镜像与客户端只在该渠道自己的更新目录里，不随公开 Release 发布。
