# v2.11.1（2026-11-13）

> 一句话：登录即可用的连接器——企业微信扫码登录后，白名单连接器自动完成授权并注册工具，不再需要第二次扫码；会话切换/登出会取消在途授权，失败静默回退到原有扫码流程。服务端新增断言端点与开关，默认关闭。

## 一、本版新增能力（登录即连）

### 1. 登录即自动完成连接器授权（免第二次扫码）

- 员工用企业微信扫码登录客户端后，服务端可为当前会话签发短时身份断言；
- 客户端用该断言向 RBAC 换取**本人**的 MCP 令牌（RFC 8693 token exchange），自动注册连接器工具；
- 白名单连接器（默认仅 `hr-data` 这类显式 OAuth 定义）可在登录后自动连接，不再弹第二次二维码/浏览器授权；
- 之后每次启动用 refresh token 自动恢复；令牌过期静默续期；
- 任何失败（服务端不可达、断言无效、用户停用、配置缺失）都**静默回退**到原有交互式扫码流程，不阻断登录。

### 2. 自动连接对会话安全（客户端加固）

- 登出/切换账号时**同步取消**在途的静默授权与自动连接，不再出现“登出后仍完成一次兑换/注册”；
- 自动连接失败不弹表单、不弹二维码、不把连接器写成误导性的“已连接”；
- 没有 refresh token 或已过期的凭据会在启动时重新静默授权，而不是永久“已连接”却不可用；
- `auth_mode=auto` 的定义不进入静默路径，避免“已连接但没有 Authorization”；
- 静默失败按连接器/步骤/分类记一条诊断日志，不记录断言或令牌。

### 3. 服务端与配置

- 新增客户端端点：`POST /api/client/v2/connectors/:id/assertion`（登录会话鉴权）；
- bootstrap 连接器目录新增 `auto_auth` / `auto_connect`（旧客户端忽略）；
- 新增部署期配置（默认关闭，见 `server/docs/03-api-reference.md`）：
  - `connector.auto_auth.enabled`、`connector.auto_auth.connectors`、`connector.auto_auth.auto_connect`；
  - `connector.assertion.issuer`、`connector.assertion.ttl`、`connector.assertion.client_id`；
- 断言签名密钥只从环境变量 `ZEOKEEL_CONNECTOR_ASSERTION_SECRET` 读取，不入库、不进日志；
- RBAC 侧需要同版本桥接（token exchange）与数据库迁移，详见配套部署说明。

## 二、升级步骤（服务端 + 客户端 + RBAC）

1. **RBAC 侧**：部署配套 token exchange 版本（含数据库迁移），配置断言密钥/签发方/客户端与 scope/resource 白名单，并预注册一个公开客户端（桌面端无 secret；需显式允许公共客户端并用断言内的 `client_id` 绑定）；
2. **ZeoKeel 服务端**：升级本版镜像，设置 `ZEOKEEL_CONNECTOR_ASSERTION_SECRET`（与 RBAC 同值）；在控制台/环境配置上述 6 个键，建议先保持 `auto_auth.enabled=false`；
3. **客户端**：随服务端镜像分发升级到 2.11.1；旧客户端不识别新字段，行为与 v2.11.0 一致；
4. **灰度**：先把 `hr-data` 加入白名单、`auto_connect=false`，验证手动点“连接”不再扫码；再打开 `auto_connect=true` 验证登录后自动连接；
5. **回滚**：关闭 `auto_auth.enabled`（或清空白名单）即回到原有扫码流程；必要时回退服务端镜像/客户端版本。RBAC 侧保留迁移与令牌端点不影响既有授权码/刷新流程。

## 三、本版边界与已知限制

- 自动授权只对**定义里含显式 `auth.tokenUrl`/`auth.scopes`** 的连接器生效；`auth_mode=auto` 的定义不进入静默路径；
- 需要 RBAC `identity.external` 已启用（登录用户能解析出 RBAC uid），否则断言端点拒绝、客户端回退扫码；
- 本版**不包含**共享电脑的聊天历史清理与启动自动恢复策略；也不自动化“一人一机器人”的文档助手绑定；
- 断言 TTL 默认 60 秒、上限 300 秒；RBAC 侧同时强制断言有效期上限；
- 公共客户端模式下，安全边界依赖“短时断言 + 一次性 `jti` + `client_id` 绑定 + 白名单 + 传输 TLS”，请勿把断言写入日志/浏览器。

## 四、升级与回滚

- **服务端**：取本版镜像压缩包 → `docker load` → 修改部署的 `SERVER_IMAGE` → `docker compose up -d`；升级前备份数据库与部署配置；
- **客户端**：随服务端镜像分发，员工从自己登录的服务器取包；
- **迁移**：本版无新增数据库迁移（与 `v2.11.0` 的库结构一致；RBAC 侧迁移不在本仓）；
- **回滚**：关闭自动授权开关即可恢复原扫码流程；客户端回退到 2.11.0 后新字段被忽略。

- **迁移清单（机器可读锚点，供 `scripts/check-release-notes-migrations.mjs` 与 `git diff` 对拍）**：无
