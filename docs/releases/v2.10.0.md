## 一、能力中心（客户端与管理端）

- **客户端信息架构**：`全部 / 已安装 / 我上传 / 市场` 四分段（带计数）、类型筛选、搜索、排序、网格/列表切换与结果计数收进统一工具条；卡片以展示名为主标题、目录名为副标题；最多两个徽章 + 状态点；详情改为面板内整页子视图。
- **客户端功能修复**：卸载后立即移除并刷新（不再回弹）；新增 `source=own` 提交面（排队中/被拒与拒因可见）；官方内容可更新；`409` 只在 `LOCAL_CONTENT` 时进入覆盖确认；上传前显示将发布的版本并本地化版本类错误；安装/卸载/上传后刷新三个分区。
- **管理端**：技能 / 智能体 / 审批三页用**中文展示名**作主标题、目录名作副标题（`display_name` 统一投影并在编辑表单可改）；统一版本空态文案、下载/调用千分位、审批时间标注服务器本地时间；修复审批预览 key 的版本段丢失、作者/归属列头解释、内置来源与锁名说明。
- **权限与术语**：能力中心四页按权限渲染写按钮；状态与来源用词与客户端对齐；移除恒 false 的「名称冲突」徽章与残留「Git 源」文案。

## 二、发布 / 删除 / 审核不变量

- **已通过版本不可删除**：`DELETE /shared-skills|agent-presets/:name/:version` 与 name 级删除返回 `409 RELEASE_APPROVED_NOT_DELETABLE`，归档与投影保持不变；停止分发请用可逆的「下架」。
- **空壳释放**：新增 `DELETE /api/server/admin/apps/:kind/:app_id`，只允许无版本、非官方的空壳；有版本/官方归属分别返回 409 指路，审计 `app_delete`。
- **统一发布内核**：`normalize` 落库改走 `appstore.Publish(AdminPublish=true)`，下架冻结、版本递增、changelog、官方/能力锁全部由内核原子判定。
- **展示版本唯一口径**：投影与交付统一取 semver 最大的 approved 版本（`PickCurrentRelease`），修复乱序批准导致的目录/下载分叉。
- **权限同权与审核原子性**：管理员直发/规范化与审批统一要求 `capability:write`；下架冻结写进同一条 `UPDATE`（`AND apps.enabled = 1`）；组织/市场/智能体三面审核统一走 `ReviewPending`；归属转移与发布共用 advisory 锁。

## 三、WASM 应用平台（生产级硬化）

- **删除与快照**：真删改为两阶段（`apps.data_cleaned_at`），冻结/删除快照在清理窗口后才真正释放数据；`current_release_id` 是运行期唯一真源，审批只部署本次批准且比当前新的版本，回滚 = 部署旧版本。
- **部署与诊断**：新增 `wasm_app_deployments` 部署历史；`wasm_call_events.version` 让诊断按实际执行版本聚合；应用级限流四轴覆盖（`NULL` = 继承全局）。
- **稳定性**：导出/快照/清理串行化（并发不再丢数据）；窗口骨架与错误上报；runtime 观测接线；审计带 `app_id`；打包 e2e 覆盖 WASM 应用打开路径，`make check` 增加 `-race` 门禁。

## 四、运行期配置入库（运维面）

- 12 个运行期旋钮从散落的 `os.Getenv` 迁到**数据库 + 控制台**：`GET/PUT /api/server/admin/config` + 管理后台「运维 → 系统配置」页；权限 `config:read` / `config:write` 仅超级管理员；写库与审计（`action=deploy_config`）同事务，非法值整批拒绝。
- **优先级**：显式环境变量（非空）> 控制台保存值 > 内置默认。存量 `.env` 行为逐字节不变；env 压过库值时配置页给「环境变量覆盖」徽标、启动日志点名、保存接口返回 warning。
- **部署面收敛**：`.env.example` 186 → 144 行；真正**引导必需**的仍是 4 个键（PG DSN / 主密钥 / 首启超管密码 / 渠道镜像路径之外的网络与证书相关项），其余运行期旋钮不再需要重启容器即可修改。详见 `docs/deploy/AI-DEPLOY.md` §2.6。

## 五、品牌标识与渠道交付

- **品牌漂移修复**：服务端门户页、`/admin/` 管理后台与内置演示应用曾显示上一个项目的旧标识，原因是私有渠道仓里公共渠道的品牌素材没有跟随公开仓的品牌变更、且既有判据只看字段与形状不看字节。本版新增**构建期字节判据**（公共渠道素材必须与 `brands/official/*` 逐字节相同），演示应用改为引用品牌真源副本（白天/夜间两版）。
- **渠道交付**：正式 tag 的发布链会构建**全部渠道**（含品牌渠道）；品牌渠道产物只发布到更新服务器自己的目录，不进入公开 GitHub Release（既有约定不变）。

## 已知限制（本版认账，未修）

- **市场版本历史 / 精选 / 审批历史面**：市场「按版本下载/版本历史」「市场审批历史面」「市场精选」「审批队列分页/批量」为产品待定项，本版未实现；现有 UI 不渲染假入口。
- **`author` 字段语义**：组织渠道表示上传者、市场渠道表示负责人；管理端已用「作者（上传者）/归属（负责人）」两列区分，接口字段未合并。
- **演示应用需要重新播种**：内置演示应用是播种数据（只落库、不随镜像热更新）。从旧版本升级后，若要看到新的品牌标识，需要删除旧的 `demo-*` 应用并重启服务端；演示数据删除不影响业务数据。
- **0090 索引非 `CONCURRENTLY`**：大表请在低峰窗口升级（见下）。

## 升级与回滚

- **服务端**：取本版镜像压缩包（GitHub Release 附件或更新服务器）→ `docker load` → 修改部署的 `SERVER_IMAGE` → `docker compose up -d`。按 `docs/deploy/AI-DEPLOY.md` 升级，**升级前必须备份数据库与数据卷**；不要使用 `latest`，不要 `down -v`。
- **客户端**：随服务端镜像分发，服务端升级后员工从自己登录的服务器取包，无需访问外网。
- **迁移**：从 `v2.9.1` 直接升级的部署，启动时会按顺序应用 `0086`–`0090`（建表 / 加列 / 索引，全部为加法迁移；预发线已含，本版相对预发线无新增）：
  - 旧版二进制与这组加法迁移兼容（可继续运行）；
  - `0090` 的索引创建不是 `CONCURRENTLY`，大表请在低峰窗口升级；
  - `0090` 的 `quality` CHECK 为 `NOT VALID`（存量不回溯，新写入立即受约束）。
- **回滚**：切回上一版镜像即可（本版无删列、无数据改写）；若已在新库上写入新格式数据，回滚前请确认可接受——本版的数据形状变化只有新增列/新增表。

- **迁移清单（机器可读锚点，供 `scripts/check-release-notes-migrations.mjs` 与 `git diff` 对拍）**：无（相对预发线 `v2.10.0-beta.4` 无新增迁移；相对上一正式版 `v2.9.1` 的 0086–0090 见上）
